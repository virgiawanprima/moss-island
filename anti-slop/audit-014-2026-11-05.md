# Audit 014 — Konsistensi web, cuaca, kedip, dan durasi keseluruhan

## Permintaan dan lingkup

Pengguna meminta perbandingan web/Tauri, pengukuran CPU/RAM/storage serta spek minimum. Lalu meminta Tauri dimatikan dan pengujian web didahulukan. Pengguna juga meminta kedip lebih jarang, animasi berkebun tetap ada, uji musim, cuaca masuk akal per musim, dan menegaskan input3 jam harus termasuk istirahat. Tauri QA sudah dihentikan; build release/pengukuran native tidak diselesaikan atas arahan tersebut. Angka minimum perangkat belum ditetapkan tanpa pengukuran release.

## Perubahan

- CSS panel menggunakan container query untuk breakpoint1024/820/680 dan kolom Musik800, sehingga lebar panel menentukan layout, bukan lebar halaman web. Sebelum perbaikan, panel960 pada browser1600 memakai kolom240/426/220 dan font51.2px, sedangkan viewport1024 memakai kolom252.141/412.625/229.219 dan font44.8px. Sesudahnya dua viewport1600 dan960 memakai kolom252.141/412.625/229.219, font44.8px dan kanvas380x160. Ini bukti konsistensi geometri web, bukan jaminan seluruh piksel identik antar engine/DPI.
- Idle pulau dan pet memakai jeda kedip bervariasi6.2–10.8 detik dan rangkaian frame asli singkat455ms. Musik berkedip setelah6.2–10.8 detik, menutup mata110ms. Kecepatan gerakan berjalan/berkebun tidak diubah.
- Cuaca: semi jeda120–240s, hujan18–30s; panas300–540s dan8–16s; gugur90–180s dan28–45s. Intensitas maksimum0.5/0.35/0.7, pengeringan65/30/95s. Dingin memakai salju; hujan dan genangan dihapus, termasuk ketika pause/ambient rain. Intensitas naik/turun bertahap. Audio ambient tidak memaksa cuaca visual. Momo menunda berkebun selama hujan nyata lalu melanjutkan menanam, menyiram dan memupuk. Ini simulasi artistik empat musim, bukan meteorologi lokasi.
- Pengaturan memakai durasi keseluruhan. Input3 jam -> total180 menit, fokus145 menit dan istirahat35 menit. Preview, penyimpanan, engine, default240 menit, dan label diselaraskan. Fase terakhir dipersingkat jika diperlukan agar total tepat. Kontrak snapshot focusTargetMin lama dipertahankan untuk sesi yang sudah ada; penyimpanan durasi baru beralih ke totalDurationMin dan konfirmasi pergantian rencana aktif tetap berlaku.

## Verifikasi

173/173 tes logika lulus, ESLint tanpa warning dan build berhasil. Tes170 membandingkan frekuensi serta kebasahan per musim;171 perpindahan dingin saat pause/ambient;172 menunda lalu melanjutkan semua aksi berkebun tanpa mengubah progres;173 input1–1440 menit termasuk180/240, jumlah fase tepat, simpan/restore engine. Tes kedip diperbarui sesuai permintaan pengguna. Tes87 memakai jadwal musiman baru. Kontrak musik lainnya tetap diuji.

Browser terlihat: laboratorium sementara .tmp/weather-lab.html memperlihatkan semi0.50, panas0.35, gugur0.70, dingin0.00/basah0.00; setelah hujan berhenti genangan masih ada dan mengering. Laboratorium mempercepat waktu secara eksplisit dan tidak dipush. Momo menanam terlihat dan tunas aktif. Fixture .tmp/season-check.html memulihkan sesi keenam1 detik dari hitungan5: semi->panas->gugur->dingin->semi, masing-masing status0/6. Ini empat penyelesaian fase nyata dengan data awal uji, bukan menunggu24 sesi penuh.

UI pengaturan asli di browser menunjukkan3 jam total,2 jam25 menit fokus,35 menit istirahat; setelah Simpan, panel utama TOTAL3 JAM dan6 putaran. Penyimpanan sempat menghasilkan timeout kontrol browser; screenshot/aksesibilitas aplikasi host mengonfirmasi penyimpanan sudah diterapkan. Jangan menganggap timeout berarti penyimpanan gagal dan mengulangi perubahan tanpa observasi. Perubahan rencana aktif dikonfirmasi pada data uji saja.

Native sebelum dihentikan: profil com.mossisland.qa memakai kode frontend sama, jendela960x308 dan screenshot aktual diperiksa. Tidak menyelesaikan uji manual empat musim native atau memverifikasi kedip/cuaca/total baru di release. Tidak menyebutnya parity1:1 terjamin. Rust tidak berubah, tes Rust tidak diulang.

## Tindak lanjut yang tertunda

Setelah pengguna melanjutkan Tauri: build release, uji tampilan terbaru di native dengan viewport/progres/musim/DPI sama; ukur pohon proses aplikasi termasuk WebView2 (bukan exe induk saja) untuk CPU dan RAM pada expanded, istirahat, musik, compact dan pet; ukur executable/aset/profil terpisah dari node_modules/target pengembangan. Nyatakan kebutuhan WebView2 dan bedakan minimum teruji dari perkiraan. Laptop pengujian: Windows11, i5-1235U10 core/12 thread, RAM sekitar32GiB. Belum ada angka CPU/RAM release atau spek minimum yang sah.
