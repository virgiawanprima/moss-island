# Perbaikan layout music player

Tanggal: 2026-10-31.
Lingkup: permintaan layout dan visual musik. Tidak mengubah provider, pencocokan lirik, clock, command media native, atau perilaku timer Fokus.

## Hasil dan keputusan desain

| Permintaan | Perubahan dan alasan |
| --- | --- |
| Kontrol di bawah judul | Previous, play/pause, next, dan repeat dipindahkan secara struktural ke `.album-info-meta` dalam satu grup. Urutan visual dan urutan keyboard tetap sama. ID tombol serta handler lama dipertahankan. |
| Repeat berikon loop | SVG loop standar menggantikan tombol teks. Mode satu lagu memiliki penanda angka 1, mode aktif memakai aksen yang sudah ada, dan semua mode memiliki aria-label/title. |
| Branding lebih besar dan tidak mepet | Padding awal grup ditambah 12 px, ikon Momo header menjadi 24 × 36 px, dan judul menjadi 1,1 rem. Font Departure Mono dan palet asli tetap dipakai. |
| Informasi lagu lebih tinggi dan sejajar | Ruang 44 px dicadangkan untuk timeline/volume agar blok cover dan metadata sejajar dengan pusat kartu lirik, bukan pusat gabungan lirik dan volume. |
| Momo mandiri di kanan | Kolom kanan tidak lagi berisi kontrol. SVG Momo desktop menjadi 84 × 98 px, dari 42 × 49 px; ukuran SVG yang diubah, bukan transform skala yang dapat bertabrakan dengan animasi. Stage sejajar dengan kartu lirik. |
| Layar sempit | Pada lebar di bawah 601 px, informasi lagu menjadi baris penuh; lirik dan Momo tetap berdampingan di baris berikutnya. Header memiliki baris navigasi tersendiri. |
| Judul panjang | Blok informasi dapat digulir dan difokuskan lewat keyboard jika kontennya melampaui ruang notch, bukan memaksakan teks keluar atau menimpa kontrol. |

Arahan visual berasal dari brief pengguna dan identitas pixel-art hutan yang sudah ada. Tidak membuat logo atau karakter baru. ENERGY 1, RHYTHM 1, MOTION 1 untuk perubahan ini: hierarki ringkas, kolom konsisten, dan tidak menambah animasi baru. Animasi Momo serta reduced-motion yang sudah ada dipertahankan.

## Berkas

1. `index.html`: pemindahan kontrol, SVG transport, grup aksesibel, dan status error di blok lagu.
2. `src/styles.css`: proporsi kolom, alignment, ukuran branding/Momo, mode ikon, fokus, serta reflow sempit.
3. `src/main.ts`: pembaruan tampilan melalui data attribute dan label aksesibel agar status polling tidak menghapus SVG. Aksi play/pause, previous, next, dan repeat tetap memakai jalur lama.
4. `tests/test_suite.ts`: tes 130 dan 131 untuk posisi/keunikan kontrol serta pelestarian ikon.

Saat menguji keyboard, ditemukan fokus hilang ketika kontrol dinonaktifkan sementara selama command berlangsung. Fokus kini dikembalikan ke tombol asal jika command selesai, sesi tetap sama, tombol sudah aktif, dan pengguna tidak memindahkan fokus ke elemen lain.

Pemeriksaan interaksi memakai bridge simulasi bawaan aplikasi, bukan mengendalikan Spotify pengguna. Pengukuran responsif menggunakan iframe same-origin dengan viewport masing-masing karena browser Playwright dalam WSL tidak dapat menjangkau loopback server Windows. Dev server lama berhenti selama sesi; setelah tidak ada listener di port 1420, `npm run dev` dijalankan kembali. Tidak menghentikan proses pengguna.

## Koreksi susulan: pusat vertikal Momo

Pengguna melaporkan Momo terlalu ke atas dan tidak center di sisi kanan. Penyebabnya bukan ukuran SVG, melainkan sisa tata letak lama: `#panel-music .col-right` masih memakai grid dua baris `minmax(0, 1fr) 44px` beserta gap 6 px dari masa kontrol berada di kolom itu. Setelah kontrol dipindah, baris 44 px menjadi kosong sehingga stage hanya menempati baris atas dan pusatnya sekitar 25 px di atas pusat kolom.

Perbaikan: kolom kanan memakai flex dengan `align-items: center` dan `justify-content: center`; stage tetap mengisi 100%. Tidak ada perubahan ukuran, animasi, atau aset Momo.

| Pemeriksaan | Hasil |
| --- | --- |
| Pusat vertikal 960 px | Pusat stage/SVG 142,23 px, pusat panel 142 px, selisih sekitar 0,23 px |
| Pusat horizontal 960 px | Pusat SVG 883 px, pusat kolom 883 px |
| 390 px | Pusat stage 361,64 px sama dengan pusat kolom; tidak ada overflow |
| Regresi | `npm test` 132/132 berhasil; tes 132 menjaga kolom kanan tidak menyisakan baris 44 px |

Pengukuran tetap berasal dari browser mock 960 × 228 px, bukan pembacaan piksel jendela Tauri native. HMR Vite menerapkan perubahan CSS ke jendela dev yang sedang berjalan.

## Koreksi susulan: lebar lirik dan ruang kosong

Pengguna melaporkan ada ruang kosong antara lirik dan sisi kanan. Penyebabnya: `#panel-music .col-center` memakai grid tanpa definisi kolom eksplisit, sementara aturan generik `.col-center` menyetel `justify-content: center`. Track implisit menjadi selebar konten (217,5 px) di dalam kolom 450 px, sehingga tersisa sekitar 116 px kosong di kiri dan kanan kartu lirik.

Perbaikan: `grid-template-columns: minmax(0, 1fr)` pada kolom lirik. Kartu lirik dan slider volume kini mengisi lebar kolom.

| Pemeriksaan | Hasil |
| --- | --- |
| 960 px | Lirik 357–807 px (lebar 450 px); jarak 8 px ke blok lagu (berakhir 349 px) dan 8 px ke kolom Momo (mulai 815 px) |
| 640 px | Lirik selebar 182 px, mengisi kolom tengah; tidak ada overflow |
| 390 px | Lirik selebar 264 px; Momo tetap di kolom 88 px; tidak ada overflow |
| Regresi | `npm test` 133/133 berhasil; tes 133 menjaga track 1fr dan kartu lirik 100% |

Catatan kejujuran: satu kali suite melaporkan 132/133 karena tes 120 membaca panggilan pertama yang kebetulan berasal dari polling bridge lama (`get_system_media_track`), bukan `fetch_lyrics`. Pengulangan segera memberi 133/133. Ini flake lama yang tercatat sebagai gotcha 27, bukan akibat perubahan CSS; tes tidak dilonggarkan.
