# Pembaruan lirik otomatis dan status konteks

Tanggal: 2026-10-31.
Rujukan vault: `Projek/moss-island/moss-island.md`, `moss-island-handoff.md`, `moss-island-gotcha.md`, dan `Jurnal/moss-island-2026-10-31.md`.

## Permintaan terbaru

Pengguna melaporkan lirik Heaven (Classic Version) oleh Bryan Adams tidak sinkron dan meminta penghapusan tombol Cari sinkron agar aplikasi menangani pemulihan sendiri.

## Temuan terverifikasi

1. Pembacaan sesi Windows nyata menunjukkan sumber Opera, judul Heaven (Classic Version), artis Bryan Adams, album Classic, dan durasi sekitar 263,221 detik. Ini bukan bukti bahwa sesi berasal dari aplikasi Spotify desktop.
2. GET LRCLIB presisi menghasilkan HTTP 200, rekaman ID 2225169, durasi 263 detik, `plainLyrics` tersedia dan `syncedLyrics` tidak tersedia pada respons tersebut.
3. Pencarian LRCLIB untuk judul versi lengkap memberikan HTTP 503 saat pemeriksaan. Karena itu, ketiadaan timestamp pada seluruh katalog tidak dapat disimpulkan hanya dari GET tersebut.
4. Pencarian Heaven tanpa label versi mengembalikan banyak rekaman lain. Nama dasar atau durasi yang mirip tidak cukup untuk memaksakan timestamp ke Classic Version.

## Perubahan

| Berkas | Tindakan |
| --- | --- |
| `src/audio/lyricsService.ts` | Lirik biasa diterbitkan segera sebagai fallback selama pencarian sinkron berlangsung. Kegagalan pencarian lanjutan tidak membuang teks yang sudah cocok. |
| `src/audio/lyricsService.ts` | Kandidat sinkron hanya diterima setelah pemeriksaan rekaman yang sama. Respons biasa tidak lagi menghentikan seluruh pencarian sebelum kandidat sinkron diperiksa. |
| `src/audio/lyricsService.ts` | Retry timestamp otomatis memakai polling sesi yang sudah ada, dengan backoff awal 30 detik sampai maksimum 5 menit; hasil kosong dicoba kembali mulai 60 detik sampai 5 menit. Error tanpa teks tetap memakai backoff jaringan. |
| `src/audio/lyricsService.ts` | Teks cache tetap terlihat ketika refresh gagal atau kosong; data sinkron yang sudah berhasil tidak diunduh ulang setiap polling. Tidak membuat timer jaringan tambahan atau timestamp perkiraan. |
| `index.html`, `src/main.ts` | Menghapus tombol Cari sinkron/Coba lirik lagi, listener-nya, dan kebutuhan retry manual. |
| `tests/test_suite.ts` | Tes 123 disesuaikan menjadi pemulihan otomatis; tes 125 sampai 129 menutup fallback teks, peningkatan ke sinkron, penolakan versi salah, backoff, dan ketiadaan tombol manual. Mock tes 15 diperbarui untuk menjawab pencarian lanjutan tanpa mengubah asersi timer. |

## Verifikasi

1. PASS, `npm test`: 129/129 tes berhasil. Warning offline dan HTTP 503 berasal dari kasus kegagalan yang sengaja dimock.
2. PASS, verifikasi browser mock: GET teks biasa berhasil, dua pencarian lanjutan mendapat 503, teks tetap tampil dengan label lirik biasa, dan tombol manual tidak ada.
3. PASS, verifikasi browser mock: sesudah data sinkron diaktifkan dan deadline retry dimajukan untuk pengujian, polling berikutnya memperbarui label dan teks menjadi sinkron tanpa klik pengguna. Total permintaan bertambah dari tiga menjadi empat. Jadwal backoff diuji terpisah pada tes 128.
4. PASS, console browser: tidak ada error pada skenario verifikasi tersebut. Mock permintaan dan fetch dikembalikan setelah pengujian.
5. Build produksi terakhir berhasil; jalankan ulang bila kode berubah lagi. Tidak ada perubahan Rust pada pembaruan penghapusan tombol ini.

## Batas dan tindak lanjut

1. Pemuatan otomatis tidak menciptakan timestamp yang tidak ada di provider. Lirik Spotify dan LRCLIB memiliki katalog berbeda.
2. Jangan menyatakan Heaven Classic sudah terbukti sinkron dari sumber nyata. Yang terbukti adalah ketersediaan teks LRCLIB, respons provider, serta mekanisme pemulihan otomatis pada tes dan simulasi.
3. Jika sinkronisasi penuh wajib untuk rekaman yang tidak memiliki timestamp LRCLIB, evaluasi provider resmi berlisensi dengan akses yang sah. Jangan memakai cookie Spotify, endpoint privat, atau mengarang waktu.

## Status Obsidian dan MCP

Empat catatan vault awal dan `AGENTS.md` sudah ditulis dan dibaca kembali sebelum tool MCP baru tersedia. Kemudian server bernama `obsidian-vault` muncul dalam katalog. Pemeriksaan `list_allowed_directories` mengembalikan hanya `D:\projects_win\moss-island`, bukan `D:\obsidian\second-brain`.

Pembaruan dalam laporan ini belum disinkronkan ke vault melalui MCP. Jangan mencoba path traversal atau memakai nama server sebagai bukti izin akses vault. Minta koreksi direktori yang diizinkan atau konfirmasi akses filesystem vault sebelum menyinkronkan pembaruan terbaru. Setelah akses tersedia, perbarui handoff, gotcha, dan jurnal yang lama: keterangan tentang tombol retry manual sudah tidak mencerminkan kode terbaru. Pertahankan bagian jurnal lama sebagai riwayat, bukan menghapusnya.
