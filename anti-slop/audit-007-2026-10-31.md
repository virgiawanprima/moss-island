# Momo Music, empat playlist lokal, dan kontrol konsisten

Tanggal: 2026-10-31. Melanjutkan permintaan pengguna dan audit 006. Pengguna memilih download audio terbaik, lalu meminta implementasi karakter Momo secara eksplisit dengan rincian gerakan, lifecycle, pengaturan, dan verifikasi.

## Arah

Moss Island tetap notch pixel art berpalet hutan, Departure Mono, Momo bertunas dan berheadphone. Layout desktop musik tetap 960 × 228 px, Momo di kanan. ENERGY 1 / RHYTHM 2 / MOTION 2 untuk panel; gerak karakter mengikuti pilihan Tenang atau Ekspresif. Gerak kecil mendominasi, tarian memiliki jeda, aksi besar jarang dan tidak dipakai dalam Tenang. Tidak ada analisis beat atau klaim sinkronisasi gerak dengan audio.

## Hambatan yang benar-benar terjadi

Build awal setelah perubahan katalog gagal karena tes lama masih memakai ID lofi/library/acoustic; tes diganti dengan katalog baru dan perilaku media bertahap, bukan dibuang. Dev CSS sempat HTTP 500 karena relative @import menuju path root yang salah, walaupun build produksi berhasil; link stylesheet eksplisit di index.html memperbaiki dev dan build. Satu percobaan suite menghasilkan 144/145 karena flake historis tes 120 menganggap log pertama pasti fetch_lyrics. Asersi kini mencari command berdasarkan identitas, mewajibkan tepat satu fetch_lyrics dan params yang benar; larangan fetch WebView serta asersi status 429 tetap ada. Kebocoran polling tes lama secara keseluruhan belum dibereskan.

Percobaan save pengaturan pertama pada browser tidak beraksi karena tombol masih disabled saat pembacaan startup mock. State diperiksa sebelum percobaan ulang; setelah tombol aktif, penyimpanan calm berhasil. Ini bukan bukti kegagalan penyimpanan aplikasi.

## Belum terverifikasi

Spotify desktop asli, ketepatan laporan stopped/changing setiap pemutar, WebView native berbagai DPI, preferensi reduced motion OS end-to-end, zoom 200 persen, pemulihan BFCache end-to-end, dan profiling CPU/RAM jangka panjang belum diuji. Pemutar yang hanya memberi paused tanpa stopped sengaja tidak dianggap selesai. Native repeat/seek tetap memakai capability dan identitas sesi lama, tidak diubah menjadi simulasi. FigCraft belum disinkronkan ulang. Tidak melakukan staging, commit, penghentian proses pengguna, atau penghapusan aset lama.

Referensi API yang dibaca: MDN HTMLMediaElement.play dan Microsoft GlobalSystemMediaTransportControlsSessionPlaybackStatus; dokumentasi resmi yt-dlp untuk bestaudio dan runtime Node. Tidak membaca cookie atau kredensial.
