# Audit fitur musik Moss Island

Tanggal 2026-11-02. Audit terbatas pada inspeksi kode musik, tes otomatis, dan satu reproduksi sintetis. Tauri tetap dimatikan sesuai permintaan pengguna sebelumnya. Tidak ada perubahan kode aplikasi pada audit ini. Prioritas antislop mengikuti R-26 dan R-27 untuk fungsionalitas serta R-35 untuk bukti verifikasi; tingkat risiko teknik dan lisensi disebut terpisah.

## Temuan

1. **Tinggi, R-27: pembatasan LRCLIB tidak dihormati.** `src-tauri/src/lyrics.rs:13-16,34-36` hanya meneruskan status dan body, bukan `Retry-After`. `src/audio/lyricsService.ts:646-703` menangkap kegagalan GET lalu meneruskan dua pencarian. Reproduksi langsung terhadap metode asli dengan fetch mock selalu HTTP 429 menghasilkan tepat tiga permintaan: `/api/get`, `/api/search`, `/api/search`. Setiap retry dapat mengulang pola; cooldown antarlagu dan jitter bersama tidak terlihat. Ini bukan bukti provider saat ini membatasi pengguna. Usulan: teruskan header, hentikan fallback untuk 429/503 dan terapkan cooldown bersama dengan jitter sesuai kebijakan provider. Riset sebelumnya di `docs/research/lyrics-robustness-2026-10-31.md`.

2. **Tinggi, R-26: kontrol bridge memiliki fallback ke sesi terbaik saat identitas kosong.** `src/audio/systemMediaBridge.ts:186-233` mengirim `sessionKey: this.currentTrack?.session_key || null`; `src-tauri/src/media.rs:696-705` menerjemahkan null atau key kosong menjadi `find_best_candidate`. Bila state berubah sebelum command mengambil currentTrack, jalur ini berpotensi mengendalikan sesi lain daripada sesi yang semula ditampilkan. UI biasanya menonaktifkan tombol pada kondisi sesi pilihan hilang, tetapi celah async belum direproduksi end-to-end. Usulan: tangkap identitas sesi saat klik, wajibkan key tidak kosong pada command kontrol, dan tolak hasil lama; seek juga wajib record key. Tes skenario ganti sesi saat command tertunda.

3. **Tinggi, R-27: sesi pilihan terputus dapat ditampilkan sebagai musik bawaan.** `src/audio/systemMediaBridge.ts:120-125,143-149` memberi `notify(null)` saat sesi hilang atau ganti pilihan. `src/main.ts:1900-1947` tanpa membedakan selected session mengganti artwork/judul ke playlist lokal dan label `PLAYLIST BAWAAN`, walaupun `updateMediaControls` menonaktifkan tombol pada sesi tertentu yang hilang (`1371-1375`). Pesan terputus hanya ada di select pengaturan (`1601-1606`). Ini observasi jalur kode, bukan reproduksi pada perangkat; bisa membuat pengguna menyimpulkan sumber sudah berpindah padahal belum. Usulan: state disconnected eksplisit yang tidak menyamar sebagai lokal; pertahankan kontrol nonaktif dan tampilkan tindakan memilih sumber.

4. **Tinggi, R-26: hasil seek lama dapat mengganggu polling sesi baru.** `src/audio/systemMediaBridge.ts:227-239` menaikkan `latestAppliedSequence` setelah seek berhasil tanpa memastikan session/record masih sama. Guard UI di `src/main.ts:1969-1972` mencegah posisi lama ditampilkan, tetapi dipanggil setelah bridge sudah mengubah urutan polling. Seek A yang selesai setelah polling B dimulai dapat menyebabkan respons B ditolak. Ini analisis urutan async, belum direproduksi di native. Usulan: tangkap identitas dan generation saat seek, cek sebelum menaikkan sequence dan sebelum refresh, dengan tes deferred.

5. **Tinggi, R-27: status gagal audio asinkron dapat menampilkan state yang bertentangan.** `src/audio/ambientSynth.ts:72-77,98-111` mengirim error callback setelah stop; callback `src/main.ts:1667-1685` langsung membuat `isAudioPlaying=false`. Handler play `2010-2012` lalu bisa return karena `!isAudioPlaying`, sebelum jalur pesan fallback dan render akhir. Callback memang menampilkan pesan detail, tetapi pemanggilan periodik `notify(null)` pada pilihan lokal (`systemMediaBridge.ts:90-94`) dapat menjalankan cabang `main.ts:1925-1949` yang mengubah label ke playlist lokal tanpa menghapus/menyelaraskan semua status. Risiko keadaan membingungkan, khususnya error lalu retry atau transisi cepat. Ini inspeksi kode; reproduksi Tauri dan observasi pesan spesifik pengguna belum diperoleh. Usulan: satu state eksplisit per sumber, tes callback error sebelum play promise selesai, retry dan ganti trek.

6. **Tinggi, R-35: kegagalan musik bawaan pada Tauri belum tertutup bukti.** Pengguna melaporkan error desktop; percobaan UI Automation hanya melihat label Putar dan waktu nol, tanpa detail penyebab, sesuai `Jurnal/moss-island-2026-11-02.md`. Pada audit ini Tauri tidak dijalankan kembali karena pengguna baru meminta dimatikan. Browser dan unit sukses bukan bukti WebView2. Usulan: setelah pengguna mengizinkan menjalankan Tauri kembali, reproduksi dengan pesan baru dan amati sourceApp/session, codec, status HTTP dan `MediaError`; uji keempat trek dan kontrol. Jangan menganggap hipotesis self-session sebagai fakta.

7. **Risiko distribusi, bukan pelanggaran visual antislop: izin empat rekaman belum diverifikasi.** `src/audio/studyMusic.ts:8-12` mereferensikan empat berkas; `public/audio/CREDITS.md:14` menyatakan lisensi redistribusi belum tersedia. Usulan: sebelum distribusi aplikasi, pastikan hak dan cakupan tiap rekaman atau ganti dengan sumber berlisensi. Keberadaan kredit atau unduhan tidak membuktikan hak distribusi.

## Batas dan rekomendasi

Urutan disarankan: verifikasi kasus 6 di Tauri dengan izin pengguna, perbaiki 2 dan 4 untuk integritas sesi, perbaiki 3 dan 5 untuk status, lalu 1 untuk ketahanan provider. Temuan 7 adalah keputusan lisensi sebelum distribusi. Laporan ini bukan audit keamanan menyeluruh dan tidak mengklaim kesiapan produksi. Tidak ada perbaikan kode yang diotorisasi atau diterapkan oleh permintaan audit.
